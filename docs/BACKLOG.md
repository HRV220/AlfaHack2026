# Бэклог — Умный кредитный кабинет предпринимателя

Бэклог разбит на эпики. Источники: бизнес-требования кейса (главный документ), ТЗ 4.2, архитектура (раздел 19 — план на 7 дней). На момент составления в репозитории есть только документация: контрактов и кода нет.

## Правила

- **Стек.** Python 3.12 на всех слоях (NFR-23, архитектура, раздел 21). Технические решения в рамках стека принимает исполнитель и записывает их в ADR.

- **Приоритет** — колонка «Пр.» из ТЗ: M (Must) / S1…S13 (Should) / C (Could). Must не урезается. Should делаются по порядку S1→S13 и урезаются в обратном порядке: S13 → S12 → … → S1 (ТЗ 3.1).
- **День** — целевой день плана из раздела 19 архитектуры; ориентир, не дедлайн.
- **Req** — ID требований ТЗ (и пунктов кейса), которые закрывает задача.
- **Статус** — `todo` / `in progress` / `done (YYYY-MM-DD)` / `отменена`; меняется по порядку выполнения в `CLAUDE.md` (шаги 1 и 6). Вопросы к разработчику и ответы по каждой задаче лежат в `docs/TASK_LOG.md`.
- **Готово, когда** — критерий приёмки эпика; задача в эпике закрыта, когда соблюдена её строка и не нарушен критерий эпика.
- Задачи — кандидаты на тикеты в трекере команды (в репозитории трекер не настроен).
- Любое изменение контракта вносится через генераторы или YAML, а не в сгенерированный JSON; изменение согласуют владельцы затронутых сервисов.
- Если к концу дня 3 эпик E06 не закрыт — вся команда переключается на него (архитектура, раздел 19).
